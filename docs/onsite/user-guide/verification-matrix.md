## Not verified in a hosted environment

- Microsoft Entra sign-in, and any Production or UAT screen with real data. These were deliberately not captured.
- Live Graph directory search results and real profile photographs. The flow was verified with a synthetic directory; the live Graph integration is covered by the release tests and the owner's pending signed-in check.
- The Mappings dialogs End ownership, Reassign ID and Correct (only the menu and History were opened), applying an import, and removal of access through an application suspension.

## Documentation gaps and UI observations

1. **Terminology varies between pages.**
   - Today says "Last recorded fingerprint"; Overview says "Latest Recorded Fingerprint".
   - The team member profile says "Activity span" instead of "Recorded Span".
   - The guide notes both.
2. **Raw identifiers are shown to users.**
   - The Access result shows the audit action as a raw key (`module_assignment.created`).
   - The Mappings "Verified" column shows "user N" instead of a name.
3. **Investigate dialog headers.** The column headers "Punches" and "Mapping Status" run together with no space.
4. **Unexplained status in an expanded row.** An expanded Daily summary row can show "Status: Details unavailable".
5. **Fixed page size on Identity Mappings.** It defaults to 20 rows per page; other pages default to 10. This is a minor difference.
6. **Older documents are out of date.**
   - The earlier end-user manual in `docs/end-user/03-diji-on-site` (unpushed branch `docs/end-user-manuals`) describes pre-0.9 behaviour.
   - This guide supersedes it for Diji On-site.
